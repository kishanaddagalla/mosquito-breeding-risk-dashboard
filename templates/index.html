01

Project Overview

The Mosquito Breeding Risk Detection System is an end-to-end Internet of Things (IoT) monitoring framework engineered to assess micro-climatic environmental conditions associated with vector mosquito reproduction. Mosquitoes, particularly species such as Aedes aegypti and Culex, require standing stagnant water, elevated relative humidity, and specific ambient thermal ranges to lay eggs (oviposition) and undergo larval incubation.

By deploying remote sensor nodes equipped with an ESP8266 / NodeMCU microcontroller, liquid detection probes, thermal sensors, and hygrometers, this system continuously evaluates the environment and calculates a dynamic Mosquito Breeding Risk Index (0-100%). The resulting data is ingested by a Python Flask backend, stored in SQLite, and rendered on a real-time web dashboard to serve as an automated early vector risk indicator for public health officers and property managers.

02

Problem Statement

Vector-borne illnesses such as Dengue, Chikungunya, Malaria, and Zika remain major global health threats. Standing stagnant water accumulated in drainage gutters, construction sites, storage tanks, and residential containers forms ideal oviposition sites for female mosquitoes.

Core Challenges:
  • Manual Field Inspection Bottlenecks: Physical door-to-door or site-by-site manual inspections are labor-intensive, reactive, expensive, and logistically unfeasible across large urban or rural sectors.
  • Invisible Micro-Climatic Spikes: High temperature and humidity combined with hidden standing water can accelerate mosquito larval incubation in as few as 4 to 7 days before human observation occurs.
  • Lack of Real-Time Warning: Traditional vector control relies on post-outbreak reporting rather than continuous predictive environmental surveillance.

04

Proposed Solution

The proposed solution is an automated, low-power IoT environmental surveillance system. The ESP8266 / NodeMCU microcontroller acts as a remote telemetry node. It samples data from connected temperature, humidity, water, and real-time clock sensors, formats the readings into a structured JSON payload, and transmits the telemetry over Wi-Fi to a Flask REST API server.

The backend server executes a weighted risk analysis algorithm, persists the entry into an SQLite relational database, and exposes REST endpoints for the web dashboard. The web dashboard dynamically refreshes cards, risk status indicators, and warning banners to deliver early vector risk notifications.

Working Principle

The operational lifecycle of the system follows an 8-step continuous feedback loop:

1

Step 1: Environmental Sampling

Physical sensors (DHT11/DHT22 and liquid water sensor) continuously gather thermal, hygrometric, and water presence state data from the monitored environment.

2

Step 2: ESP8266 Sensor Input Reading

The ESP8266 microcontroller reads analog voltage from the water probe pin and digital pulse streams from the DHT sensor and DS3231 RTC clock module.

3

Step 3: Microcontroller Data Processing

Firmware validates data boundaries, converts raw analog values to boolean water presence status, and packages data into a formatted JSON string payload.

4

Step 4: Wi-Fi Transmission

The ESP8266 establishes a Wi-Fi connection and issues an HTTP POST request carrying JSON payload data to the server endpoint (/api/sensor).

5

Step 5: Backend Ingestion & SQLite Storage

The Python Flask server parses the request, timestamps the entry, and inserts the raw readings into the SQLite sensor_readings table.

6

Step 6: Risk Analysis Engine Execution

The backend evaluates environmental parameters against biological scoring weights to calculate the total risk score (0-100%) and risk category (LOW, MODERATE, HIGH).

7

Step 7: Web Dashboard Rendering

The web dashboard fetches the latest telemetry via AJAX polling and updates live metric cards, the SVG risk gauge, and analytics charts.

8

Step 8: Early Risk Warning Trigger

If the risk level transitions to HIGH or stagnant water is detected, the frontend triggers warning alerts and glowing visual status pulses.

09

Risk Analysis Engine

The risk analysis engine computes a composite Mosquito Breeding Risk Index based on biological constraints of mosquito oviposition and larval development.

Risk Calculation Model Breakdown (Max 100 Points):

  • Stagnant Water Factor (45 Points): Stagnant water is an essential baseline requirement for oviposition. If detected = +45 pts; if absent = 0 pts.
  • Temperature Factor (35 Points): Optimal larval development range (25.0°C - 32.0°C) = +35 pts; moderate growth range = +20 pts; suboptimal = +5 pts.
  • Relative Humidity Factor (20 Points): High moisture (≥ 65.0%) prolongs adult mosquito lifespan = +20 pts; moderate (45.0% - 65.0%) = +10 pts; low = +4 pts.

Data Flow Pipeline

Data transition from physical phenomenon to user dashboard display:

  1. Physical Phenomenon: Air temperature, humidity, and water conduction create voltage/digital signals.
  2. Hardware Conversion: ESP8266 ADC converts water probe voltage; digital protocol decodes DHT readings.
  3. JSON Structuring: Telemetry is formatted into HTTP JSON headers: {"temperature": float, "humidity": float, "water_detected": bool, "rssi": int, "battery_level": int}.
  4. Network Transport: Payload travels across 802.11 b/g/n Wi-Fi to HTTP port 5000.
  5. API Processing: Flask parses JSON, validates data types, triggers calculate_risk() function, and executes SQLite INSERT query.
  6. UI Rendering: Frontend JavaScript fetches JSON via /api/latest, updates SVG dash-offsets, updates text labels with count-up animation, and updates Chart.js datasets.

API Communication Specification

Documentation for the microcontroller REST API endpoint used by the ESP8266:

POST /api/sensor

Request Payload (JSON):

{
    "temperature": 28.5,
    "humidity": 78.0,
    "water_detected": true,
    "node_id": "NODE-01",
    "rssi": -65,
    "battery_level": 88,
    "species": "aedes"
}

Response Payload (JSON):

{
    "status": "success",
    "message": "Sensor reading recorded successfully",
    "data": {
        "id": 142,
        "node_id": "NODE-01",
        "timestamp": "2026-10-08 19:00:00",
        "temperature": 28.5,
        "humidity": 78.0,
        "water_detected": true,
        "risk_level": "HIGH",
        "risk_score": 100,
        "risk_reason": "Stagnant water present | Temperature in optimal range | High humidity",
        "incubation_days": 6.5,
        "rssi": -65,
        "battery_level": 88
    }
}

Field Definitions:

  • temperature (Float): Ambient temperature reading in degrees Celsius (°C).
  • humidity (Float): Relative atmospheric humidity percentage (%).
  • water_detected (Boolean): Liquid presence status (true = stagnant water detected, false = dry).
  • node_id (String, optional): Sensor node identifier (default: NODE-01).
  • rssi (Integer, optional): Wi-Fi signal strength in dBm (e.g., -65).
  • battery_level (Integer, optional): Battery percentage (0-100).
  • species (String, optional): Target species profile: aedes, culex, or anopheles.
  • risk_level (String): Calculated risk classification (LOW, MODERATE, HIGH).
  • risk_score (Integer): Computed risk score ranging from 0 to 100.
  • incubation_days (Float): Estimated egg-to-adult mosquito hatching days at current temperature.

System Advantages

  • Continuous Surveillance: Eliminates manual physical inspection delays with 24/7 automated monitoring.
  • Real-Time Early Warning: Alerts property owners and health teams before adult mosquitoes emerge.
  • Remote Accessibility: Web-based dashboard accessible from any desktop or mobile browser.
  • Low-Cost Implementation: Built using affordable, standard off-the-shelf microcontrollers and sensors.
  • Historical Analytics: Provides time-series logging for trend analysis and seasonal vector planning.
  • Modular & Scalable Architecture: Supports addition of multiple remote sensor nodes across wide geographic zones via GIS map.
  • Multi-Species Profiling: Risk calibration switchable between Aedes, Culex, and Anopheles species profiles.
  • Hardware Health Monitoring: Live Wi-Fi RSSI and battery diagnostics prevent silent node failures.

Technical Limitations

Technically Honest Assessment:
  • Sensor Precision Dependence: Accuracy depends directly on the calibration and quality of connected physical sensors.
  • Experimental Calibration Needed: Threshold values require environmental tuning based on specific local climate variations.
  • Surveillance vs Direct Bio-Detection: System estimates environmental suitability for mosquito breeding rather than directly detecting mosquito larvae or adult insects biologically.
  • Network Dependency: Web monitoring requires an active Wi-Fi and network connection for real-time dashboard transmission.
